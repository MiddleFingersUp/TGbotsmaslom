# TGbots

Платформа для разработки индивидуальных Telegram-ботов с AI-агентами для российского бизнеса.

**Статус проекта:** Initial Documentation / Pre-development — реализованного кода приложения пока нет, проект находится на этапе проектирования и подготовки документации.

---

## Какую проблему решает продукт

Компании сферы услуг в России теряют клиентов из-за того, что:

- заявки с Telegram-каналов и сайтов обрабатываются вручную и с задержкой;
- менеджеры отвечают на однотипные вопросы (цены, расписание, условия) вместо продаж;
- консультации недоступны в нерабочее время;
- контакты потенциальных клиентов не фиксируются системно.

TGbots решает эту проблему: для каждого заказчика разрабатывается AI-агент, который общается с клиентами в Telegram на русском языке, консультирует по услугам, собирает заявки (лиды) и при необходимости передаёт диалог живому сотруднику.

## Для кого предназначен

- **Заказчики** — компании сферы услуг (салоны, студии, клиники, сервисные центры и т. п.), которые хотят автоматизировать первичную консультацию и сбор заявок в Telegram.
- **Оператор (разработчик проекта)** — один разработчик, который создаёт и сопровождает ботов под каждого заказчика. SaaS-панели самообслуживания для конечных заказчиков в MVP нет.

## Бизнес-модель

Индивидуальная разработка под заказ (Custom Development): каждый бот настраивается под конкретную компанию — каталог услуг, FAQ, тексты, сценарии передачи диалога человеку. Проект мульти-тенантный: данные каждого заказчика (tenant) изолированы.

## Основные возможности (планируемые для MVP)

- Интеграция с Telegram (aiogram 3.x, webhook/polling).
- Общение на русском языке через облачные LLM API (с абстракцией провайдера).
- Структурированный каталог услуг компании и FAQ.
- Консультация по услугам, ценам и условиям на основе **только проверенных данных**.
- Выявление потребностей клиента и рекомендация подходящих услуг.
- Обработка типовых возражений.
- Сбор контактных данных и заявок (лид-менеджмент).
- Передача диалога живому сотруднику (human handoff).
- Хранение истории диалогов в PostgreSQL.
- Базовый мониторинг и логирование.

## Принцип работы (концептуально)

1. Клиент пишет боту компании в Telegram.
2. Входящее сообщение проходит через Telegram-интеграцию в приложение.
3. Agent Core формирует контекст диалога и обращается к LLM через единый интерфейс провайдера.
4. Для фактов (цены, доступность, расписание) агент использует инструменты (tools), которые запрашивают данные из проверенных источников — базы знаний, каталога услуг, backend-логики.
5. Ответ валидируется, сохраняется история, ответ доставляется клиенту в Telegram.
6. Заявки, контакты и события handoff фиксируются в базе данных и доступны оператору.

Ключевое ограничение: AI не придумывает цены, скидки, доступность и правила компании. Все бизнес-критичные операции проверяются backend-логикой.

## Технологический стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.12+ |
| Телеграм-интеграция | aiogram 3.x |
| API-слой | FastAPI |
| Валидация | Pydantic 2 |
| БД и ORM | PostgreSQL, SQLAlchemy 2, Alembic |
| Векторный поиск (позже) | pgvector (опционально) |
| LLM | Облачные LLM API через абстракцию провайдера |
| Деплой | Docker Compose |
| Тесты | pytest |
| VCS | Git |

В обязательный MVP **не входят**: Redis, микросервисы, веб-панель, сложная инфраструктура.

## Планируемые этапы разработки

> Этапы ориентировочные; детальный план будет зафиксирован в `docs/DEVELOPMENT_PLAN.md`.

1. **Фаза 0 — Проектирование (текущая):** продукт, архитектура, схема БД, требования безопасности, план разработки.
2. **Фаза 1 — Каркас:** скелет модульного монолита, конфигурация, CI, тестовое окружение (pytest, Docker Compose).
3. **Фаза 2 — База данных и tenant-модель:** схема с `tenant_id`, миграции Alembic, изоляция данных.
4. **Фаза 3 — Telegram-интеграция:** приём/отправка сообщений, webhook, rate limiting.
5. **Фаза 4 — Agent Core и LLM-провайдер:** контекст диалога, абстракция провайдера, токен-трекинг, валидация ответов.
6. **Фаза 5 — Знания и инструменты:** каталог услуг, FAQ, инструменты агента с валидацией входов/выходов.
7. **Фаза 6 — Лиды и handoff:** сбор заявок, передача диалога живому сотруднику.
8. **Фаза 7 — Безопасность и подготовка к запуску:** аудит секретов, приватность, правовая проверка (152-ФЗ), пилотный заказчик.

## Запуск проекта

### 1. Требования
- Python 3.12+
- Docker и Docker Compose (для развёртывания PostgreSQL)

### 2. Установка виртуального окружения
```bash
python -m venv .venv
source .venv/bin/activate  # Linux/macOS
# или для Windows:
.venv\Scripts\activate

pip install -e ".[dev]"
```

### 3. Запуск тестов и линтеров
```bash
pytest
ruff check .
mypy src tests
```

### 4. Запуск приложения в режиме разработки
```bash
uvicorn src.main:create_app --factory --reload --port 8000
```
Проверка доступности: `GET http://localhost:8000/health`
